ROMAN / User-Oriented UML

Как работает система целиком

Эта диаграмма показывает ROMAN глазами пользователя: от момента отправки запроса до получения результата. Она упрощает внутреннюю архитектуру и делает акцент на порядке взаимодействия между основными компонентами.
1. Точка входа Пользователь общается с системой через CLI или через Mattermost.
2. Оркестратор Агент принимает запрос, собирает контекст сессии и решает, что делать дальше.
3. Модель LLM анализирует запрос и определяет: можно ответить сразу или нужны инструменты.
4. Навыки и действия При необходимости агент подгружает скиллы и запускает действия во внешних системах.
5. Результат Ответ собирается, сохраняется в сессию и возвращается пользователю в исходный канал.

Общий порядок взаимодействия компонентов

Ниже показан основной рабочий цикл: пользователь отправляет запрос, агент подготавливает контекст, модель принимает решение по следующему шагу, а затем агент либо сразу отвечает, либо использует подходящий навык как инструмент для обращения во внешние системы и формирования итогового ответа. 

sequenceDiagram
autonumber
actor User as Пользователь
participant Entry as CLI / Mattermost
participant Agent as Агент ROMAN
participant Session as Хранилище сессии
participant Skills as Менеджер скиллов
participant LLM as LLM / OpenAI API
participant Tools as Навыки и инструменты
participant Systems as Внешние системы

User->>Entry: Отправляет вопрос или команду
Entry->>Agent: Передает текст запроса
Agent->>Session: Получает или создает сессию
Session-->>Agent: История диалога и состояние
Agent->>Skills: Собирает доступные навыки
Skills-->>Agent: Инструкции, инструменты, контекст
Agent->>LLM: Отправляет запрос вместе с контекстом и списком инструментов

alt Ответ можно дать сразу
  LLM-->>Agent: Финальный текст ответа
else Нужны действия или проверки
  LLM-->>Agent: Запрос на вызов инструмента
  alt Нужный навык еще не загружен
    Agent->>Skills: Загружает подходящий скилл
    Skills-->>Agent: Добавляет новые действия и правила
  end
  Agent->>Tools: Выбирает и использует нужный навык
  Tools-->>Agent: Возвращает логику и параметры действия
  Agent->>Systems: Выполняет действие через выбранный навык
  Systems-->>Agent: Возвращает данные или статус
  Agent->>LLM: Передает результат обратно в модель
  LLM-->>Agent: Формирует понятный итоговый ответ
end

Agent->>Session: Сохраняет обновленную сессию
Agent-->>Entry: Возвращает итоговый ответ
Entry-->>User: Показывает результат в том же канале
Смысл этой схемы в том, что агент выступает центральным координатором: он не просто отправляет запрос в модель, а управляет контекстом, подключает нужные навыки и сам обращается во внешние системы с их помощью, после чего возвращает пользователю собранный и понятный ответ.
